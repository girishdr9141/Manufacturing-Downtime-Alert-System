# Product Requirements Document (PRD): Enterprise DX Command Center Frontend

## 1. Project Overview
**Name:** Enterprise DX Command Center
**Description:** A zero-trust, full-stack progressive web application (PWA) designed to monitor manufacturing edge devices, handle automated IT support tickets, provide AI-assisted diagnostic runbooks, and allow for bi-directional remote IoT commands.
**Backend Architecture:** Fully Serverless on AWS (API Gateway, Lambda, DynamoDB, IoT Core, SNS).

## 2. Goals & Objectives
- **Monitor:** Real-time visibility into machine health and fleet status.
- **Manage:** Interactive IT support ticketing system for anomalous events.
- **Control:** Secure execution of Cloud-to-Device (C2D) commands via MQTT.
- **Analyze:** Export data and visualize trends over time.

## 3. Tech Stack Recommendations
*This PRD is framework-agnostic, but the following are highly recommended for an enterprise build:*
- **Framework:** Next.js (App Router) or Vite (React)
- **Styling:** Tailwind CSS + Shadcn UI (for premium glassmorphic/enterprise feel)
- **State Management:** Zustand or React Query (for API caching)
- **Maps:** Leaflet.js (`react-leaflet`) for factory floor GPS mapping
- **Charts:** Recharts or Chart.js for data visualization

## 4. User Interface Architecture

### 4.1 Authentication View (Zero-Trust Gateway)
- **Purpose:** Securely connect the frontend to the AWS API Gateway.
- **Components:**
  - Glassmorphic login card.
  - Input field for: `API Gateway Invoke URL` (e.g., `https://xxxxx.execute-api.region.amazonaws.com/prod`).
  - Validation: Ensure no trailing slashes and valid HTTPS URL.
  - Action: Save URL to `localStorage` or Global State and transition to the Dashboard.

### 4.2 Main Dashboard View
The dashboard should be a responsive CSS Grid/Flexbox layout with a dark-mode-first aesthetic (`bg-slate-900`).

#### A. Global Navigation / Header
- Project Title ("Enterprise DX Command Center").
- "Export CSV" Button (Triggers `GET /export` endpoint).
- "Toggle Theme" Button (Light/Dark mode).

#### B. Live Factory Map (Component)
- **Purpose:** Visualize edge devices geographically.
- **Features:** 
  - Render an interactive map.
  - Hardcode or dynamically place pins for `PLASMA-GEN-001`, `002`, `003`.
  - Color code pins based on global ticket status (Red = Error, Green = Healthy).

#### C. System Health Analytics (Component)
- **Purpose:** High-level overview of fleet status.
- **Features:**
  - Donut chart displaying the ratio of Healthy vs. Error machines.

#### D. Active IT Support Tickets (Component)
- **Purpose:** Display and manage tickets fetched from DynamoDB.
- **Features:**
  - Fetch tickets periodically or on-load from `GET /tickets`.
  - Filter out tickets where `Status === 'RESOLVED'`.
  - Render a list of cards for each active ticket.
  - **Ticket Card Data:**
    - `TicketID`, `MachineID`, `Priority`, `CreatedAt`
    - `Description` (e.g., "Machine entered state ERROR_POWER_LOSS")
    - `AIRunbook` (Step-by-step diagnostic instructions generated by backend).
  - **Ticket Actions:**
    - Dropdown: "Assign Technician"
    - Button: "Resolve Ticket" (Triggers `PUT /tickets` with `{ ticket_id, action: 'RESOLVE' }`).

#### E. Cloud-to-Device Control Panel (Component)
- **Purpose:** Execute remote override commands via AWS IoT Core.
- **Features:**
  - Dropdown: Select Target Machine (e.g., `PLASMA-GEN-001`).
  - Buttons: `STOP` (Red), `START` (Green), `Push OTA Firmware` (Yellow).
  - Action: Triggers `POST /commands` with payload `{ machine_id, command }`.
  - Feedback: Display a Toast notification upon successful API response.

## 5. API Integration Specifications
All API calls must handle CORS appropriately. If API Gateway "Lambda Proxy Integration" is misconfigured, responses may be double-stringified. The frontend should gracefully parse `response.body` if necessary.

### 5.1 Fetch Tickets
- **Endpoint:** `GET {API_URL}/tickets`
- **Response Type:** Array of Objects
- **Data Model:**
  ```json
  [
    {
      "TicketID": "INC-D5BCCCC3",
      "MachineID": "PLASMA-GEN-001",
      "Priority": "HIGH",
      "Status": "OPEN",
      "Description": "Machine entered state ERROR_POWER_LOSS.",
      "AIRunbook": "AI DIAGNOSTIC: 1. Isolate power...",
      "CreatedAt": "2026-07-26 10:07:18 UTC"
    }
  ]
  ```

### 5.2 Resolve Ticket
- **Endpoint:** `PUT {API_URL}/tickets`
- **Payload:**
  ```json
  {
    "ticket_id": "INC-D5BCCCC3",
    "action": "RESOLVE"
  }
  ```
- **Action:** Upon 200 OK, refetch the tickets list to remove the resolved ticket from the UI.

### 5.3 Send Remote Command
- **Endpoint:** `POST {API_URL}/commands`
- **Payload:**
  ```json
  {
    "machine_id": "PLASMA-GEN-001",
    "command": "STOP"
  }
  ```
- **Action:** Triggers IoT shadow updates. Show success Toast.

### 5.4 Export Data
- **Endpoint:** `GET {API_URL}/export`
- **Action:** Direct the browser to download the response as a `.csv` file. Easiest implementation: `window.open(API_URL + '/export')`.

## 6. Error Handling & Resilience
- **Network Failures:** Wrap all fetch calls in `try/catch`. Display user-friendly Toast notifications for "Failed to connect to API" rather than silently failing.
- **Data Validation:** Ensure arrays are returned before attempting `.map()` or `.filter()` to prevent React crashes.
- **Loading States:** Display skeleton loaders or spinners while fetching data from AWS.
